## 1. 요약

토크메이트는 `app-ideas-hobbies.md`의 3-7번 아이디어 'AI 회화 파트너(롤플레이 상황극)'를 실제로 만든 결과물입니다. 하루 동안 아래 순서로 진행했습니다.

1. **자료 조사와 기획(PRD v0.1 → v0.2)**: 경쟁 앱, OpenRouter 모델, 브라우저 음성 기능, 교정 방식 연구를 조사했습니다. 사용자 결정 사항을 반영해 기획서를 확정했습니다.
2. **첫 버전 구현**: 음성 입력, 문장별 즉시 교정, 힌트·번역, 미션, 리포트, PDF·Word·Excel 내보내기까지 갖춘 단일 페이지 앱을 만들었습니다.
3. **디자인 시안(Café Notebook)**: 줄 공책과 빨간 펜 첨삭을 중심으로 한 디자인 가이드와 7개 화면 시안을 만들었습니다.
4. **배포 후 개선**: 실제 사용에서 나온 문제를 고쳤습니다.
   - 마이크 '음성이 감지되지 않았습니다' 오류
   - 보낸 문장이 입력창에 다시 남는 문제
   - 스페인어 인식률이 낮은 문제
   - 힌트 버튼을 찾기 어려운 문제
5. **디자인 적용**: 시안을 실제 앱에 옮겼고, 기존 기능은 그대로 유지했습니다.

## 3. 단계별 개발 과정

### 3.1 아이디어 선정과 자료 조사
- **출발점**: 전공·취미 기반 앱 아이디어 50선 중 3-7번 'AI 회화 파트너'를 골랐습니다. 상황(공항, 식당, 호텔)을 고르면 AI가 외국어로 대화를 이어 가고 수준에 맞춰 교정하는 앱입니다.
- **경쟁 앱 조사**:
  - Speak: 체계적인 초급 과정이 강점입니다.
  - Praktika: 아바타 튜터가 강점이지만 문화적 뉘앙스는 부족합니다.
  - Talkpal: 57개 언어와 다양한 롤플레이가 있지만 높은 수준에서는 내용이 얕습니다.
  - 공통 한계: 모두 구독형이고, 상황·교정 방식·저장 형식을 사용자가 바꾸기 어렵습니다.
- **차별점 정리**:
  - 구독료 없이 쓴 만큼만 내고, 호출 전에 예상 비용을 보여 줍니다.
  - 상황과 교정 강도를 직접 정합니다.
  - 기록을 내 PC에 파일로 남깁니다.
  - 3개 언어를 한 앱에서 연습합니다.
- **교정 방식 연구**:
  - 자연스럽게 바꿔 말해 주기(recast)는 대화 흐름과 심리적 부담 면에서 유리합니다.
  - 명시적 교정은 학습자가 실제로 고쳐 말하는 비율이 높습니다.
  - 그래서 **대화 안에서는 recast, 화면 옆(첨삭 노트)에서는 명시적 교정**을 함께 쓰기로 했습니다.
- **기술 조사**:
  - 브라우저 음성 인식(Web Speech API)은 Chrome·Edge에서 안정적이고, Firefox에서는 기본으로 지원하지 않습니다.
  - jsPDF는 한글 글꼴을 넣어야 하므로 PDF는 브라우저 인쇄를 쓰기로 했습니다.
  - 모델 ID와 단가는 OpenRouter 비교 페이지를 참고했습니다.

### 3.2 기획: 로그인·DB가 꼭 필요한가?
사용자 질문에 대한 결론은 **필요 없음**이었습니다.

| 질문 | 판단 |
|---|---|
| 여러 사람이 쓰는가? | 본인 혼자 사용 |
| 여러 기기에서 이어서 쓰는가? | 파일로 저장하면 충분 |
| API 키를 서버에 숨겨야 하는가? | 각자 브라우저에서 자기 키를 입력하므로 불필요 |
| 기록이 계속 쌓여야 하는가? | 내보낸 Excel로 관리(나중에 불러오기 기능으로 확장 가능) |

**사용자 결정 사항 (PRD v0.2에 반영)**

| 항목 | 결정 |
|---|---|
| API 키 보관 | 기본은 sessionStorage(탭을 닫으면 삭제), 선택하면 localStorage에 저장 |
| 언어·수준 | 영어 초중급(A2+), 일본어 중급(B1·N3), 스페인어 초급(A1) |
| 주 사용 환경 | PC Microsoft Edge, 갤럭시 삼성 인터넷. 첫 버전부터 음성 입력 포함 |
| 교정 시점 | 대화 중 문장마다 즉시 |
| 설정 기억 | localStorage에 기억(키 제외) |
| 이름·배포 | 토크메이트(TalkMate). GitHub 저장소와 배포는 사용자가 직접 진행 |

### 3.3 첫 버전 구현 (v0.2)
- **구조**: 빌드 과정이 없는 파일 3개(`index.html`, `style.css`, `app.js`)로, GitHub Pages에 그대로 올릴 수 있습니다.
- **화면 4개**: API 키 입력 → 연습 설정 → 회화 → 리포트, 그리고 설정 대화 상자.
- **AI 역할 분담**:
  - 대화 상대: Gemini 3.8 Flash. 스트리밍으로 첫 글자가 빨리 보입니다.
  - 문장 교정: GPT-6 Luna. 매 턴 호출되므로 싸고 빠른 모델을 골랐습니다.
  - 리포트: Claude Sonnet 5.5. 한 번만 호출되며 품질이 중요합니다.
- **모델 구성 프리셋**: 기본 / 고품질 / 절약.
- **교정**: 응답을 JSON으로 받아 처리합니다. 주는 정보는 다음과 같습니다.
  - 틀린 부분, 고친 문장, 오류 유형(12종), 한국어 설명
  - 더 자연스러운 표현, 이번 문장으로 달성한 미션 번호
- **음성**:
  - 입력: 브라우저 음성 인식으로 받습니다. 인식된 문장은 보내기 전에 고칠 수 있습니다.
  - 출력: 브라우저 음성 합성으로 읽어 줍니다. Edge의 'Natural' 음성을 우선 고르고, 언어별 목소리와 속도를 정할 수 있습니다.
- **비용**: OpenRouter 응답의 실제 비용(usage)을 기록해 누적 비용과 역할·모델별 내역을 보여 줍니다. 연결 테스트 때 모델 목록 API로 단가를 자동으로 갱신합니다.
- **내보내기**:
  - PDF: 인쇄용 스타일 + 브라우저의 'PDF로 저장'
  - Excel: SheetJS로 7개 시트
  - Word: docx.js로 리포트 형식
  - 라이브러리는 버튼을 누를 때만 불러옵니다.
- **안전**:
  - AI 출력은 `textContent`로만 화면에 넣습니다(HTML로 해석하지 않음).
  - 키는 내보내기 파일에 넣지 않습니다.
  - 대화를 저장하지 않은 채 탭을 닫으려 하면 확인 창을 띄웁니다.
  - 진행 중인 대화는 sessionStorage에 임시 보관해 새로고침해도 이어 할 수 있습니다.

### 3.6 배포 후 문제 해결 ①: 마이크 '음성이 감지되지 않았습니다'
- **증상**: 배포한 사이트에서 마이크를 누르면 계속 '음성이 감지되지 않았습니다'가 떴습니다.
- **원인 분석**: 한 문장만 듣는 설정이라 몇 초 동안 조용하면 바로 끊겼습니다. 또 실패해도 어느 단계에서 막혔는지 알 수 없었습니다.
- **개선**:
  - PC에서는 연속으로 듣고, 조용해서 끊기면 최대 60초까지 자동으로 다시 듣습니다. 안드로이드는 결과 중복 문제가 있어 한 문장씩 듣고 다시 시작합니다.
  - 마이크 열림 → 소리 감지 → 말소리 감지 단계를 기록해 실패 원인을 다르게 안내합니다.
  - 설정에 **마이크 테스트**를 추가했습니다. 5초 동안 입력 레벨, 사용 중인 장치 이름, 연결된 마이크 목록을 보여 줍니다.
  - README에 Edge·삼성 인터넷 문제 해결 순서를 정리했습니다. Windows 기본 입력 장치, 권한, `edge://settings/content/microphone` 등을 다룹니다.
- **결과**: 사용자 환경 설정을 바로잡아 해결했습니다.

## 4. 현재 시스템 구조

### 4.1 파일 구성

### 4.4 AI 호출 구성
| 역할 | 기본 모델 | 방식 | 최대 출력 토큰 | 출력 |
|---|---|---|---|---|
| 대화 | Gemini 3.8 Flash | 스트리밍 | 900 | 상황극 대사(텍스트) |
| 교정 | GPT-6 Luna | 일반 | 1,500 | JSON(고친 문장, 오류, 자연스러운 표현, 미션) |
| 힌트 | GPT-6 Luna | 일반 | 800 | JSON(표현 3개, 읽기, 한국어 뜻) |
| 번역 | GPT-6 Luna | 일반 | 500 | 한국어 번역 |
| 미션 생성 | GPT-6 Luna | 일반 | 600 | JSON(직접 만든 상황의 미션 3개) |
| 리포트 | Claude Sonnet 5.5 | 일반 | 4,000 | JSON(총평, 미션 평가, 잘한 점, 연습할 점, 표현, 다음 추천) |
| 받아쓰기(선택) | Gemini 3.8 Flash | 오디오 입력 | 500 | 들은 그대로의 문장 |

- **오류 처리**: 429·5xx 응답과 네트워크 오류는 1회 자동 재시도합니다. 오류는 이해하기 쉬운 한국어로 안내합니다(401 키 오류, 402 크레딧 부족 등).
- **JSON 해석**: 코드 블록이나 앞뒤 설명이 섞여 있어도 JSON을 찾아냅니다. 실패하면 '다시 시도' 버튼을 보여 줍니다.

### 4.5 프롬프트 설계 원칙
- **대화 상대**:
  - 정해진 역할을 유지하고, 수준(CEFR)별 어휘와 문장 길이를 지킵니다.
  - 대부분 질문으로 끝내 대화를 이어 갑니다.
  - 학습자의 오류는 설명하지 않고 바르게 바꿔 말해 줍니다(recast).
  - 미션 달성을 자연스럽게 유도합니다.
- **교정**:
  - 음성 인식 결과의 구두점·대소문자는 무시합니다.
  - 맞지만 어색한 문장은 오류가 아니라 '더 자연스러운 표현'으로 안내합니다.
  - 한국어로 말하면 그 표현을 외국어로 알려 줍니다.
- **받아쓰기**: 문법 오류를 고치지 말고 들은 그대로 적게 합니다. 말소리가 없으면 `[NO_SPEECH]`를 돌려받습니다.

### 4.6 음성 처리
| 단계 | 브라우저 방식(기본, 무료) | AI 받아쓰기(선택) |
|---|---|---|
| 입력 | Web Speech API(`continuous` PC, 단문 반복 안드로이드) | MediaRecorder 녹음(최대 30초) |
| 처리 | 브라우저 회사 서버(Microsoft·Google) | 16kHz 모노 WAV → OpenRouter `input_audio` |
| 장점 | 무료, 실시간 글자 표시 | 학습자 억양에 강함, 오류를 그대로 받아씀 |
| 단점 | 비원어민 억양에 약함 | 1~2초 지연, 1원 안팎 비용, 실제 모델 검증 필요 |

## 7. 알려진 제한 사항

1. **실제 환경 미검증**: AI 응답 품질, 교정 정확도, AI 받아쓰기는 실제 OpenRouter 키로 충분히 검증되지 않았습니다.
2. **모델 ID·단가 변동**: 모델 이름과 가격은 바뀔 수 있습니다. 연결 테스트로 확인하지만, 모델이 없어지면 설정에서 직접 바꿔야 합니다. Gemini 3.8 Flash 할인가는 2027-01-01에 두 배가 될 예정입니다.
3. **기록 누적 없음**: 대화가 끝나면 파일로만 남습니다. 지난 기록을 앱에서 다시 보거나 약점을 누적 분석하는 기능은 없습니다.
4. **발음 평가 없음**: 받아쓴 글자를 교정할 뿐, 발음 자체(억양·음소)는 평가하지 않습니다.
5. **브라우저 의존**:
   - 음성 인식은 Edge·Chrome·삼성 인터넷에서만 됩니다(Firefox는 AI 받아쓰기나 타자 입력만 가능).
   - 음성 합성 품질은 기기에 설치된 목소리에 따라 다릅니다.
6. **긴 대화 비용**: 대화가 길어지면 매 턴 전체 기록을 보내므로 입력 토큰이 늘어납니다(요약 기능 없음).
7. **API 키 노출 위험**: 브라우저에 키를 두는 구조라, 악성 확장 프로그램 등에 노출될 수 있습니다. OpenRouter 사용 한도 설정을 권장합니다.
8. **단일 파일 구조**: `app.js`가 약 1,940줄이라 기능이 늘수록 수정 범위를 파악하기 어려워집니다.
9. **외부 리소스 의존**: Google Fonts와 CDN 라이브러리가 막히면 글꼴이 바뀌고 Word·Excel 내보내기를 쓸 수 없습니다.
