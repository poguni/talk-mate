                      1. 개요

                      1.1 배경

                      외국어 회화는 "실제로 말해 보는 시간"이 가장 부족합니다. 시중 앱(Speak, Praktika, Talkpal 등)은 롤플레이와 AI 튜터를 제공하지만 월 구독료가 들고, 상황·교정 방식·저장 형식을 내 마음대로 바꾸기 어렵습니다.

                      이 앱은 이미 가진 OpenRouter API 키 하나로 Claude Sonnet 5.5, GPT-6 Luna, Gemini 3.8 Flash를 불러, 상황극 회화와 교정을 쓴 만큼만 비용을 내고 이용하는 개인용 도구입니다.

                      1.2 시장 조사 요약

                      앱 강점 한계 이 앱에 반영할 점
                      Speak 초급자용 체계적 과정, 롤플레이 난이도 상승 구독형, 지원 언어 제한 난이도(CEFR)별 상황 설계
                      Praktika 아바타 튜터, 목표 기반 수업 문화적 뉘앙스 부족, 안정적 연결 필요 목표 표현(미션) 제시
                      Talkpal 57개 언어, 여행·업무 롤플레이, 음성 통화 모드, 토론 높은 수준에서 내용이 얕음, 발음 피드백 약함 다양한 상황 + 사용자 정의 상황
                      ChatGPT 등 범용 챗봇 자유도 높음 매번 프롬프트를 새로 써야 함, 교정·통계가 체계적이지 않음 상황·교정 프롬프트를 앱이 대신 관리

                      출처는 문서 끝 "참고 자료"에 있습니다. 비교 블로그 기반이므로 세부 수치는 참고용입니다.

                      차별점 1. 구독료 없이 사용량만큼 과금되고, 호출 전에 예상 비용을 보여 줍니다. 2. 상황·난이도·교정 강도를 사용자가 직접 정합니다. 3. 대화 기록과 교정 노트를 PDF·Word·Excel 파일로 내 PC에 남깁니다. 서버에는 아무것도 저장하지 않습니다. 4. 영어·일본어·스페인어 3개 언어를 한 앱에서 연습합니다.

                      1.3 목표

                      • 상황(공항, 식당, 호텔 등)을 고르면 1분 안에 회화 연습을 시작합니다.
                      • 말하기(음성) 또는 타자(텍스트)로 대화하고, 문장마다 교정과 더 자연스러운 표현을 받습니다.
                      • 대화가 끝나면 요약(새로 쓴 표현, 오류 유형 통계)을 받고 파일로 저장합니다.
                      • 로그인, 서버, DB 없이 브라우저만으로 동작합니다.

                      1.4 범위에서 제외하는 것 (Non-goals)

                      • 로그인, 회원가입, 서버 백엔드, 클라우드 DB, 기기 간 동기화
                      • 정밀한 발음 평가(음소 단위 점수). 브라우저 음성 인식 결과를 원문과 비교하는 수준까지만 다룹니다.
                      • 실시간 음성 대화 API(초저지연 음성 대 음성) 연동
                      • 단어장 SRS 기능(별도 앱 3-2에서 다루고, 이 앱은 Excel 내보내기로 연결)

                      2. 로그인·DB가 꼭 필요한가? (질문 (3)에 대한 답)

                      결론: 필요하지 않습니다. 원하시는 방식(키 입력 → 회화 연습 → 필요하면 파일로 저장)에는 로그인과 DB가 없는 구조가 더 알맞습니다.

                      질문 로그인·DB가 필요한 경우 이 앱의 상황
                      여러 사람이 쓰는가? 사용자별 데이터 분리가 필요 본인 혼자 사용
                      여러 기기에서 이어서 쓰는가? 클라우드 동기화 필요 파일로 저장해 두면 됨
                      API 키를 서버에 숨겨야 하는가? 남에게 앱을 공개하고 내 키로 서비스할 때 각자 자기 키를 브라우저에서 입력하므로 서버 불필요
                      기록이 계속 쌓여야 하는가? 장기 통계를 서버에서 계산 내보낸 Excel 파일을 다시 불러와 누적(선택 기능)

                      로그인·DB가 없을 때 감수할 점 - 브라우저를 닫으면 진행 중이던 대화는 사라집니다. 대화가 끝나면 파일로 저장해야 합니다(종료 시 저장 안내 창 표시). - 기기를 바꾸면 이전 기록을 자동으로 볼 수 없습니다. 저장한 파일로 확인합니다.

                      3. 사용자와 사용 시나리오

                      3.1 주 사용자

                      • 본인(개발자 겸 유일한 사용자): 영어·일본어·스페인어를 공부하며, 여행을 자주 다닙니다. 데이터 분석에 익숙해 Excel로 학습 기록을 정리하는 것을 좋아합니다.

                      3.2 대표 시나리오

                      다음 달 스페인 여행 전에 식당 주문 상황을 연습하려고 합니다. 스페인어 수준은 A2입니다.

                      1. GitHub Pages 주소로 앱을 열고 OpenRouter API 키를 입력합니다.
                      2. 언어(스페인어), 수준(A2), 상황(식당: 주문과 계산)을 고릅니다. 화면에 "이번 대화의 미션"(예: 추천 메뉴 묻기, 알레르기 말하기, 계산서 요청하기)과 예상 비용(약 몇십 원)이 표시됩니다.
                      3. AI 웨이터가 스페인어로 말을 걸고, 브라우저가 소리 내어 읽어 줍니다.
                      4. 마이크 버튼을 누르고 스페인어로 대답합니다. 막히면 힌트 버튼으로 한국어 도움말과 예시 문장을 봅니다.
                      5. 내 문장 옆에 교정 결과가 표시됩니다: 틀린 부분, 고친 문장, 더 자연스러운 표현, 짧은 설명(한국어).
                      6. 10~15턴 후 대화 종료를 누르면 요약 리포트(미션 달성 여부, 새로 쓴 표현, 오류 유형 통계, 다음 연습 추천)가 나옵니다.
                      7. PDF로 저장(대화 전문과 리포트), Excel로 저장(교정 노트, 표현 목록)을 눌러 PC에 보관합니다.
                      8. 브라우저 탭을 닫으면 API 키와 대화 내용이 모두 사라집니다.

                      4. 전체 사용 흐름

                      [0. 키 입력]   OpenRouter API 키 입력(이번 세션에만 보관), 연결 테스트
     ↓
[1. 연습 설정] 언어 · 수준(CEFR) · 상황 · 교정 방식 · 입력 방식(음성/텍스트) · 모델 선택
     ↓          → 미션과 예상 비용 표시
[2. 회화]      AI 상대 발화(TTS) ↔ 내 발화(음성 인식/타자)
     ↓          → 문장별 교정, 힌트, 번역 보기, 다시 말하기
[3. 리포트]    미션 달성, 새 표현, 오류 유형 통계, 추천 연습
     ↓
[4. 저장]      PDF · Word · Excel (+ 선택: JSON 백업)

                      5. 기능 요구사항

                      우선순위: P0(MVP 필수), P1(2차), P2(있으면 좋음)

                      F0. API 키와 설정 (P0)

                      ID 요구사항 우선순위
                      F0-1 OpenRouter API 키를 화면에서 입력. 코드에 하드 코딩하지 않음 P0
                      F0-2 키는 기본으로 sessionStorage에 보관하여 탭(세션)을 닫으면 삭제. 선택 시 localStorage에 저장해 다음에 다시 입력하지 않음 P0
                      F0-3 "연결 테스트" 버튼: 짧은 요청으로 키가 유효한지 확인 P0
                      F0-4 "키 지우기" 버튼: 즉시 삭제 P0
                      F0-5 모델 슬러그(OpenRouter 모델 ID)는 설정에서 수정 가능. 연결 테스트 때 OpenRouter 모델 목록으로 ID를 확인하고 단가를 갱신 P0
                      F0-6 키 입력란은 type="password", 화면·내보내기 파일·콘솔 로그에 키를 출력하지 않음 P0

                      F1. 연습 설정 (P0)

                      ID 요구사항 우선순위
                      F1-1 언어 선택: 영어, 일본어, 스페인어 (확장 가능한 구조) P0
                      F1-2 수준 선택: CEFR A1~C1과 A2+(초중급) (일본어는 JLPT N5~N1 병기). 기본값: 영어 A2+ 초중급, 일본어 B1 중급(N3), 스페인어 A1 입문·초급 P0
                      F1-3 상황 선택: 기본 상황 목록(아래 표)에서 선택 P0
                      F1-4 사용자 정의 상황: 장소·내 역할·AI 역할·목표를 직접 입력 P0
                      F1-5 상황마다 미션 2~4개를 AI가 생성하거나 기본값 사용 P0
                      F1-6 교정 방식: 대화 중 문장마다 즉시 교정(확정). 대화 후 몰아서 교정·교정 끄기는 P2 P0
                      F1-7 AI 말 속도·길이 조절(짧게/보통/길게), 존댓말·반말(일본어·스페인어 tú/usted) 선택 P0
                      F1-9 설정(언어·수준·말투·상황·모델·음성)을 localStorage에 기억 P0
                      F1-8 여행 대비 모드: 여행 국가·도시를 입력하면 현지 상황(예: 마드리드 지하철, 오사카 이자카야)으로 상황을 맞춤 P0

                      기본 상황 목록 (초안)

                      분류 상황
                      여행 공항 체크인·입국 심사, 호텔 체크인·문제 해결, 식당 주문·계산, 길 묻기·대중교통, 쇼핑·환불, 약국·병원
                      일상 자기소개·스몰토크, 취미 이야기, 전화 예약
                      학습 자유 대화(주제 지정), 토론(찬반), 사진 묘사(P2)

                      F2. 회화 진행 (P0)

                      ID 요구사항 우선순위
                      F2-1 AI가 상황 속 역할로 먼저 말을 걸고, 수준에 맞는 어휘·문장 길이로 대화를 이어 감 P0
                      F2-2 텍스트 입력 P0
                      F2-3 음성 입력: Web Speech API 음성 인식(크롬·엣지). 인식 결과를 보내기 전에 수정 가능 P0
                      F2-4 AI 발화 음성 재생: 브라우저 음성 합성(speechSynthesis). 다시 듣기, 속도 조절 P0
                      F2-5 힌트: 지금 할 만한 말 2~3개를 예시로 제시(한국어 설명 포함) P0
                      F2-6 번역 보기: AI 발화를 한국어로 보기(기본은 숨김, 클릭 시 표시) P0
                      F2-7 응답을 스트리밍으로 표시해 기다리는 시간을 줄임 P0
                      F2-8 미션 체크리스트: 대화 중 달성한 미션을 자동 표시(직접 체크도 가능) P0
                      F2-9 다시 말하기: 교정 받은 문장을 다시 말해 보고 일치율 표시 P1
                      F2-10 모르는 단어 클릭 → 뜻과 예문 보기, 표현 목록에 담기 P2

                      F3. 문장별 교정 (P0)

                      ID 요구사항 우선순위
                      F3-1 내가 보낸 문장마다 교정 결과를 JSON으로 받아 표시: 원문, 고친 문장, 틀린 부분 강조, 오류 유형, 한국어 설명 1~2줄 P0
                      F3-2 더 자연스러운 표현 1~2개 제안(문법상 맞아도 원어민이 더 자주 쓰는 표현) P0
                      F3-3 오류 유형 분류(예: 시제, 관사, 성·수 일치, 어순, 조사, 어휘 선택, 높임말, 철자) P0
                      F3-4 대화 상대 AI는 대화 흐름을 깨지 않도록 자연스럽게 바꿔 말하기(recast)만 하고, 명시적 교정은 별도 패널에 표시 P0
                      F3-5 교정이 틀렸다고 생각되면 "이의 있음" 표시 → 다른 모델로 재검토(P2) P2

                      설계 근거: 연구에 따르면 자연스럽게 고쳐 말해 주기(recast)는 대화 흐름과 심리적 부담 면에서 유리하고, 명시적 교정은 학습자가 실제로 고쳐 말하는 비율이 더 높습니다. 그래서 대화 안에서는 recast, 화면 옆에서는 명시적 교정을 함께 제공합니다.

                      F4. 대화 후 리포트 (P0)

                      ID 요구사항 우선순위
                      F4-1 미션 달성 여부, 총 턴 수, 내 발화 단어 수 P0
                      F4-2 오류 유형별 횟수 표와 막대그래프 P0
                      F4-3 오늘 새로 쓴 표현 / 꼭 외울 표현 5~10개 (원문, 뜻, 예문) P0
                      F4-4 잘한 점 1~2개, 다음에 연습할 점 1~2개 (한국어) P0

                      6. AI 연동 설계

                      6.1 OpenRouter 기본 사항

                      • 엔드포인트: POST https://openrouter.ai/api/v1/chat/completions (OpenAI 호환 형식), stream: true 지원
                      • 인증: Authorization: Bearer <사용자가 입력한 키>
                      • 권장 헤더: HTTP-Referer(앱 주소), X-Title(TalkMate)
                      • 브라우저에서 직접 호출(서버 프록시 없음)

                      6.2 모델과 역할 분담 (기본값 제안, 설정에서 변경 가능)

                      역할 기본 모델 OpenRouter ID(조사 기준, 개발 시 확인) 단가(입력/출력, 100만 토큰당) 선택 이유
                      대화 상대(롤플레이) Gemini 3.8 Flash google/gemini-3.8-flash $0.75 / $3.75 (프로모션가, 2027-01-01부터 $1.50 / $7.50 예정) 빠른 응답, 다국어 자연스러움
                      문장별 교정·힌트 GPT-6 Luna openai/gpt-6-luna $0.10 / $0.50 매 턴 호출되므로 저렴하고 빠른 모델, JSON 출력
                      대화 후 리포트 Claude Sonnet 5.5 anthropic/claude-sonnet-5.5 $2 / $10 한 번만 호출, 설명 품질이 중요
                      • "고품질 모드": 교정도 Claude Sonnet 5.5로 수행(비용 증가).
                      • "절약 모드": 세 역할 모두 GPT-6 Luna.

                      6.3 예상 비용 (15턴 대화 1회 기준, 대략)

                      항목 호출 수 토큰(대략) 비용(대략)
                      대화 상대 15회 입력 누적 약 30,000 / 출력 약 1,500 약 $0.03
                      교정 15회 입력 약 15,000 / 출력 약 4,500 약 $0.004
                      리포트 1회 입력 약 5,000 / 출력 약 1,500 약 $0.025
                      합계 약 $0.06 (약 80원)

                      단가와 환율은 바뀔 수 있으므로 앱은 설정값으로 계산하고, 실제 비용은 응답의 usage 정보로 기록합니다.

                      6.4 프롬프트 원칙

                      • 대화 상대: 상황, 역할, 수준(CEFR)별 어휘·문장 길이, 한 번에 1~3문장, 질문으로 끝내 대화를 이어 감, 사용자의 오류는 자연스럽게 바꿔 말하기만, 미션 유도.
                      • 교정: 반드시 JSON 스키마로 응답. 오류가 없으면 "errors": []. 설명은 한국어. 수준보다 지나치게 어려운 대안 표현은 제안하지 않음.
                      • 리포트: 대화 전문과 교정 결과를 입력으로 받아 JSON 생성 → 앱이 화면과 파일로 변환.
                      • 대화 기록이 길어지면 앞부분을 요약해 입력 토큰을 줄임(P1).

                      6.5 교정 JSON 예시

                      {
  "original": "Yo quiero un mesa para dos.",
  "corrected": "Quiero una mesa para dos.",
  "errors": [
    {"span": "un mesa", "fix": "una mesa", "type": "성·수 일치", "explain_ko": "mesa는 여성 명사이므로 una를 씁니다."}
  ],
  "natural": ["¿Tienen una mesa para dos?"],
  "note_ko": "주어 yo는 생략하는 것이 더 자연스럽습니다."
}

                      6.6 안정성

                      • 요청 실패 시 1회 자동 재시도, 이후 오류 메시지와 "다시 시도" 버튼
                      • 교정 JSON 파싱 실패 시 원문만 표시하고 대화는 계속 진행
                      • 대화 상대와 교정을 병렬로 호출해 기다리는 시간을 줄임

                      7. 음성 기능

                      기능 기술 비고
                      음성 인식(STT) Web Speech API SpeechRecognition (lang: en-US, ja-JP, es-ES) 주 사용 환경인 PC Edge와 갤럭시 삼성 인터넷에서 동작. 파이어폭스는 기본 미지원 → 텍스트 입력으로 대체
                      음성 합성(TTS) speechSynthesis 대부분의 브라우저 지원. 언어별 음성 목록에서 선택
                      • 개인정보 안내: Edge·크롬·삼성 인터넷의 음성 인식은 음성을 브라우저 회사(마이크로소프트·구글) 서버로 보내 처리할 수 있습니다. 앱 첫 화면에 안내합니다.
                      • 음성 선택: Edge의 "Natural" 온라인 음성을 우선 선택하고, 설정에서 언어별 목소리와 속도를 바꿀 수 있습니다.
                      • 음성 인식 결과는 바로 보내지 않고 입력창에 넣어 수정할 수 있게 합니다.
                      • (P2) 브라우저 음성 인식 대신 OpenRouter 음성 전사 엔드포인트 사용 옵션(추가 비용 발생).

                      8. 데이터와 보안

                      8.1 API 키 보관 방식 (확정)

                      요청하신 "localStorage에 저장 + 세션이 끝나면 사라짐"은 브라우저 저장소의 특성상 다음과 같이 구분됩니다.

                      방식 동작 장단점
                      sessionStorage (권장) 탭을 닫으면 자동 삭제. 새로고침해도 유지 "세션이 끝나면 사라짐"을 브라우저가 보장. 탭마다 따로 입력
                      localStorage + 종료 시 삭제 코드 페이지를 떠날 때 코드로 삭제 브라우저 강제 종료·충돌 시 삭제 코드가 실행되지 않아 키가 남을 수 있음. 새로고침해도 지워짐
                      localStorage (지우기 전까지 유지) 직접 지울 때까지 보관 매번 입력할 필요 없음. 공용 PC에서는 위험

                      → sessionStorage를 기본값으로 하고, 키 입력 화면과 설정에서 "이 기기에 저장(localStorage)" 옵션을 제공합니다. 옵션을 끄면 localStorage의 키를 즉시 지웁니다.

                      8.2 데이터 보관

                      데이터 위치 수명
                      API 키 sessionStorage(기본) 또는 localStorage(선택) 탭 닫으면 삭제 / 직접 지울 때까지
                      진행 중인 대화·교정 메모리 + sessionStorage(새로고침 대비) 탭 닫으면 삭제
                      설정(언어·수준·말투·상황·모델 슬러그·단가·음성) localStorage (키 제외) 설정 초기화할 때까지 유지
                      대화 기록·리포트 사용자가 내보낸 파일(PDF·Word·Excel) 사용자의 PC

                      8.3 보안 원칙

                      • API 키는 OpenRouter 외 어디로도 보내지 않으며, 내보내기 파일에 포함하지 않음.
                      • AI 출력은 HTML로 해석하지 않고 텍스트로만 표시.
                      • 외부 스크립트는 버전을 고정한 CDN에서만 로드.
                      • OpenRouter 대시보드에서 키별 사용 한도(크레딧 한도) 설정을 권장.

                      안전 표시 textContent로만 렌더링 AI 출력을 HTML로 해석하지 않으므로 별도 정화 라이브러리 불필요
